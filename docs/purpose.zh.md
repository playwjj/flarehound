# 流量按用途

FlareHound 按 UA、网络、IP、路径拆分流量——这些回答「谁来了」；真正决定处置的是「**为什么来**」。同样量级的两个 UA，处置可以完全相反：训练爬虫（拦了几乎无损失）、用户在助手里提问时触发的抓取（背后是真人需求，拦了等于拦需求）、抓取 API 代其客户取数（B2B 数据消费，适合限速 / 收费 / 引导官方 API，而不是封 IP）。用途分面把这个答案放进日报、控制台和报警。

不新增数据源、不新增令牌、没有写路径，也从不自动处置。

## 六类

| 类别 | 定义 | 典型成员 | 报告措辞倾向 |
|---|---|---|---|
| `training` 训练 | 为训练模型采集语料 | GPTBot、ClaudeBot、CCBot、Bytespider、Meta-ExternalAgent | 拦了几乎无回流损失 |
| `search` 搜索索引 | 为搜索（含 AI 搜索）建索引 | OAI-SearchBot、Claude-SearchBot、PerplexityBot、Applebot | 带来引用与回流，慎拦 |
| `user_action` 用户触发 | 用户提问时助手实时抓取 | ChatGPT-User、Claude-User、Perplexity-User、Meta-ExternalFetcher | 背后是真人，按真人对待 |
| `tool` 工具代客 | 抓取 API / 平台代其客户取数 | Exa、Firecrawl、Diffbot、rednote-websearch-bot | B2B 数据消费：限速、收费、引导 API |
| `mixed` 混合 | 搜索与训练一体 | Googlebot、Bingbot、Amazonbot | 运营商不拆分，老实标混合 |
| `undeclared` 未申报自动化 | 具自动化特征的浏览器 UA | 跑在云机器上的无头浏览器舰队 | **只报特征，不下 AI 结论** |

不属于以上类别的 UA 不打标签：分面只覆盖 AI 相关爬虫与未申报自动化，不做全量 bot 百科（AhrefsBot 等 SEO 爬虫不在表内）。

## 标签从哪里来

- **内置映射表**：社区维护的 [ai.robots.txt](https://github.com/ai-robots-txt/ai.robots.txt) 清单快照（UA → 运营商 → 用途；Cloudflare Radar 的 AI 流量统计以同一清单为底表），随版本发布，**运行时从不联网拉取**。匹配不区分大小写：精确匹配优先，其次是被包含的最长标记。
- **你的覆盖表**：`config.json` 的 `purposes`，或控制台 **设置 → ASN 名称 → 流量用途**：填 UA 子串与类别（`none` 表示从所有类别移除）。覆盖优先于内置表；控制台中的修改和其他设置一样进审计。
- **可信度随标签呈现**：
  - *已验证*——该 UA 至少 90% 的请求通过 Cloudflare 已验证机器人检查（`cf.client.bot`）；
  - *自报*——UA 自称如此，但未经验证（谁都可以写「GPTBot」）；
  - *按特征*——未申报自动化。
- **未申报自动化**：来自**机房 / 云网络**（FlareHound 网络表与归档记录的注册名）的浏览器 UA（Chrome、Firefox、Safari、Edge），或无头浏览器。需要 ASN 维度：Free 套餐不判定，报告会注明。这是关于特征的结论，任何地方都不会写成「疑似某家 AI」。
- **展示时映射、不落盘**：归档只存 UA 原文，用途在渲染报告或页面时按当前映射表实时查；清单修订后历史口径一致跟随。日报注明映射表版本。

## 日报

UA Top 之后新增一节：

```
流量按用途（映射表 2026-11-20 版；所读 UA 分组覆盖 97% 的请求）：
- 未申报自动化 41.0%：240,512 次（昨日 29.0%，+48.2%）——具自动化特征的浏览器 UA（机房网络出口、无头浏览器）；Top：Chrome/157.0.0.0 (X11; Linux x86_64) 214,057（AS45102 aliyun 98%）、…
- 搜索索引 18.0%：…；Top：Applebot 12,400 [已验证]、…
- 训练 6.0%：…；Top：GPTBot 8,000 [已验证]、ClaudeBot 3,100 [已验证]、…
- 工具代客 2.0%：…；Top：rednote-websearch-bot 7,598 [自报]、…
```

每类给出占窗口请求的百分比、次数、昨日占比与环比、Top 3 UA 及可信度。某类占比较昨日变动 **10 个百分点**及以上时，结论行点名（「用途占比变化：未申报自动化 29% → 41%（+12 个百分点）」）。每份日报多两次 GraphQL 查询（本窗口与前一天，UA × 网络 × 已验证机器人，各 2,000 组）。

## 报警

新 UA 面孔进入 Top 10 时带用途：`新面孔 UA 进入 Top 10：「…」，9,000 次【训练 · OpenAI · 已验证】`。

- 已验证（或本套餐无法验证）的新**训练**爬虫**只记录、不报警**：照常进归档、写日志，并在日报中列出（「新训练爬虫面孔（只记录、不报警）」）。
- 自报而未验证的训练 UA 照常报警并带标签——它可能是任何人。
- 新的 `tool` 与 `undeclared` 面孔照现行口径报警，带标签。

不改任何阈值数值：只改措辞，外加训练类例外。

## 控制台

- 涨降榜、新面孔、实时面孔、拦截榜与下钻列表中的 UA 旁显示用途徽标（悬停显示运营商与可信度）。列表没有流量证据，徽标只按映射表；是否已验证、是否未申报自动化见下钻。IP 不加徽标——用途是 UA 的属性。
- 涨降榜（UA）与新面孔页面**按用途过滤**。
- **下钻**：UA 显示其标签与可信度（已验证 / 自报 / 按特征）；ASN 显示其流量按用途的构成——「AS45102 由什么组成」一张表回答。

## 命令行

```
flarehound purpose [--zone NAME] [--hours 24] [--asn 45102]
```

输出最近 N 个整小时（对比前一天同时段）的上述一节，可针对整个 zone 或某个网络的切片（只读令牌）。

## doctor

`flarehound doctor` 输出映射表版本、条目数与生效的覆盖条数。映射表无法读取时功能自动关闭——日报、控制台、报警与没有该功能时完全一致——`doctor` 会说明原因。
