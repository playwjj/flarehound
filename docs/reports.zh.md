# 告警、日报与建议 {#alerts-daily-report-suggestions}

每条消息都是纯文本，结论先行，使用英文或中文（`report.language`）。除文本外，每条消息还携带结构化字段（`kind`、`zone`、`decision`、窗口、触发的 `rules`），由 webhook 和 JSONL 渠道透传——见 [通知渠道](channels.md)。

| `kind` | 发送时机 |
|---|---|
| `intraday` | 小时级看守的决策为 `alert`、`changed`、`escalate` 或 `recovered`（[检测](detection.md#alert-discipline)） |
| `daily` | 每天 `schedule.daily_report_at` |
| `audit` | 自定义规则集发生变化，且重新体检发现了问题（[WAF 规则体检](audit.md)） |

## 消息怎么读 {#how-a-message-reads}

每条消息都按同一个顺序写：**结论 → 证据 → 细节**。先一句话说清发生了什么、要不要管，再给关键数字，技术细节放在最后（或在控制台里）。

- 对比一律写成 *「现在的值（之前的值，变化）」*：「137（前一天 37，约 3.7 倍）」。翻倍以上写成「约 N 倍」，变化不到 1% 写「持平」，之前为 0 写「新出现」。
- 访问者用人能认出来的名字：「Go 程序（Go-http-client/1.1）」「Chrome 131 · Windows」「爬虫 Googlebot」；只有浏览器外壳、没有浏览器版本的标识会被标为「不完整的浏览器标识（多为脚本冒充浏览器）」。
- FlareHound 自身的状态（套餐限制、令牌权限、本地历史、计数口径）不是新闻：日报只在它**变化时**显示，没变化则每周提醒一次。查询失败（数据缺口）则每次都说。

用词对照（旧版本里的说法 → 现在的说法）：

| 以前 | 现在 |
|---|---|
| 越线 | 超出平时范围 / 需要关注 |
| 基线 | 平时水平（过去 4 周同时段，或前一天） |
| dynamic | 需要源站处理的请求（未命中缓存） |
| zone 总请求 | 总请求 |
| UA Top / ASN Top | 主要访问者 / 主要来源网络 |
| 新面孔 | 新的访问者 / 新的来源网络 |
| 机制假设、证伪点 | 可能的原因、排除条件 |
| 封锁候选 | 可以考虑封禁的 IP |
| 固定检查点 | 例行检查 |
| 记账底量 | Cloudflare 日常就有的 522/524 记录 |

## 小时告警 {#intraday-alert}

```
FlareHound · example.com — 发现异常
⚠️ 需要关注：Worker web 调用量上涨、Worker web 单次运行变慢、需要源站处理的请求变多 等 5 项
时间 2026-11-17 08:00–09:00 (Asia/Shanghai)

▶ 需要源站处理的请求变多
没有命中缓存、需要源站（或 Worker）实时处理的请求：70,000（昨日同时段 40,000，+75%）。
→ 建议：看下方「回源最多的路径」，找出是哪些页面没走缓存。

▶ 出现新的来源网络：EXAMPLE-HOSTING-AS (AS207990)
45,000 次请求，昨天还不在前 25 名。这是机房 / 云服务器网络，真人访客很少从这里来。
→ 建议：如果不是你自己的服务或合作方，可以考虑挑战或拦截（见下方处置建议）。

流量概况（对比昨日同时段）：
- 总请求：152,000（昨日同时段 100,000，+52%）
- 需要源站处理的请求（未命中缓存）：70,000（昨日同时段 40,000，+75%）
- 源站报错（5xx）：5（昨日同时段 5，持平）；502 ×5

来源细节：
- 回源最多的路径：/rank 35,000（昨日 20,000）
- AS207990 主要访问：/rank 35,000

可能的原因：
- [可能性高] 爬虫 / 机器人在加量：新来源 AS207990 约占增量的 87%。
  如果出现以下情况，就不是这个原因：该来源的路径分布与常态访客一致、且来自宽带/移动网络……

处置建议（只读——FlareHound 不会执行，请在 Cloudflare 面板自行实施）：
1. 封禁 AS207990 (EXAMPLE-HOSTING-AS, 机房/云网络)
   ...
```

各部分依次为：

1. **前两行**——站点与消息类型，然后用大白话写出*需要关注什么*（后果最重的在前：故障与报错，其次是成本，再次是流量，最后是新访问者）。
2. **每个问题一段**——标题；数字连同之前的值（*「137（前一天 37，约 3.7 倍）」*）；它最可能意味着什么（流量没涨而报错变多，指向源站自身；流量涨了而回源没涨，说明被缓存挡住了……）；以及 **→ 建议：** 一个具体的下一步。最多五段，其余每项一行列出。
3. **流量概况**——总请求、需要源站处理的请求、源站报错（5xx，附占源站回应的比例和状态码拆分）、Cloudflare 连不上源站（52x，附 522/524 判断）、源站响应时间（P95）、各 Worker；过去 4 周的平时水平生效时一并显示。
4. **来源细节**——只在确实要发消息时才采集；查询失败绝不会阻塞告警。
5. **可能的原因**——每条都标出可能性高低，以及出现什么情况就能排除它。没有站得住的原因时，消息会说明先只报数字。
6. **可以考虑封禁的 IP** 与 **处置建议**——见下文。恢复消息只有一行。

邮件收到的是同一份报告的 HTML 版并附图表，Telegram、Discord 和企业微信以图片形式收到图表——见 [图表与 HTML](channels.md#charts-and-html-reportvisuals-default-on)。

### 严重度：是声势大，还是真的疼？ {#severity-is-it-loud-or-does-it-hurt}

被缓存挡住的流量突增——总请求或 Worker 调用上涨、出现新访问者，但**需要源站处理的请求（`dynamic`）涨幅低于 15%**，且回源、CPU、源站报错、源站变慢/连不上、骤降、路径等指标都正常——会作为单独的结论以**轻微**（🟡）报告：*「增量被缓存挡住了：需要源站处理的请求 +1.0%，CPU 和源站报错都正常——源站和 Worker 没有压力。观察即可，无需处理。」*Worker CPU 中位数上涨若能由 P99 和调用量解释为**请求构成变化**（且没有其他昂贵项），同样是轻微：*「轻微：请求构成变化导致 Worker CPU 波动」*。任何昂贵或出故障的情况都是**高**严重度。JSONL 记录带有 `severity: "low" | "high"`。

### 面板口径与网络标签 {#dashboard-terms-and-network-labels}

一旦 [口径校准](archive.md#calibration) 有了数据，每个问题里的请求数都会附上面板口径的等价值——*「（按 Cloudflare 面板口径约 9,080 次）」*——因为人们习惯用面板上的数字思考。新 ASN 会标注其注册名称和网络类型——*「AS45102 [ALIBABA-CN-NET，机房/云网络]」*——这样做决定前不用再去查（名称查询需要 `clientASNDescription` 维度；内置表不需要它也能用）。

### 贵贱分离 {#expensive-vs-cheap}

流量按 `cacheStatus` 拆分：`hit`、`stale`、`updating` 和 `revalidated` 是**廉价**的；其他一切（`dynamic`、`miss`、`bypass`、`expired`、未知值）都是**昂贵**的。真实渲染（`dynamic`）放在最前面，并与其他缓存未命中分开显示——它才是值班的人盯着的那个数字。

### 机制假设 {#hypotheses}

由固定规则产生，例如：

- 某个新面孔承担了 ≥ 80% 的增量 → 高置信度；≥ 50% → 中置信度。
- ≥ 70% 的增量落在廉价流量上 → 「廉价流量，实际成本小」。
- dynamic 上涨而总量持平 → 可缓存性下降。
- CPU 上涨而调用量持平 → 部署变更或慢路径。
- 源站 5xx，附按路径的分布；≥ 80% 集中在一条路径 → 是某个路由的缺陷，而非源站故障。
- 其他情况 → 没有集中的驱动因素，证据不足。

### 封锁候选 {#block-candidates}

- 占比是相对**增量**（当前 − 基线）计算的。没有增量就没有候选：流量持平时的 CPU、5xx 或骤降异常，绝不会建议封 IP。
- 单个 IP 承担 ≥ 5% 增量时会被列出，并附一键命令（`flarehound block ip … --for 24h`）。
- 每一行 IP——封锁候选、Top 客户端 IP、日报中被拦最多的 IP 以及 FlareHound 的封锁项——在加载了国家库时都会附上其 [归属地](configuration.md#geoip)：`106.201.104.211 [IN · India]`，或在 `report.language: zh` 时显示为 `106.201.104.211 [印度 (IN)]`。这是注册/路由所在国家，而非运营者所在国家，并且它从不改变报告的内容。
- 如果可封锁的最大 IP 承担不到 1%，来源就是**分散的**：消息会说明逐个封 IP 无济于事，并指向 ASN 或路径层面的处置。
- Cloudflare 自己的网段（通常是某个 Worker 在调用你的站点）、私有 / 保留网段以及 `blocking.never_block` 中的条目会作为「集中但不可封锁」单独列出，并注明原因。
- 自称已知爬虫却未通过核验的 UA 会被点名为**冒充者**。

## 处置建议 {#suggestions}

建议是只读的意见；每条都附有证据、预期收益、影响、回滚方式，并且——在 FlareHound 能执行的情况下——附上 [一键封锁](blocking.md) 或 [规则变更](rules.md) 模块的一键命令。每条消息最多 6 条。

| 类型 | 触发条件 | 建议 | 一键命令 |
|---|---|---|---|
| 封锁 ASN | 该 ASN 解释了 ≥ 20% 的增量，**且**是机房/云网络 | 封锁 `(ip.geoip.asnum in {N}) and not cf.client.bot` | `flarehound block asn N --action block --for 24h` |
| 质询 ASN | 同上，但为住宅/骨干网络或未知网络 | 托管质询，明确*不*封锁 | `flarehound block asn N --for 24h` |
| 质询路径 | 某条敏感路径的线被越过，或它解释了 ≥ 30% 的 dynamic 增量 | 对该路径启用托管质询 | `flarehound rules add --action managed_challenge …` |
| 限速 | 一条路径解释了 ≥ 50% 的 dynamic 增量，来源分散，且尚未被质询建议覆盖 | 按 IP，20 次请求 / 10 秒，托管质询 | `flarehound ratelimit add --path … --requests 20 --period 10` |
| 缓存 | 某条静态资源路径（js、css、图片、字体、媒体、pdf、xml、wasm …；不含 json）出现在 Top dynamic 路径中，且请求数 ≥ `min_count` | 边缘缓存规则，TTL 1 天（文件名带内容哈希时为 1 年） | `flarehound cache add --path … --ttl 1d` |
| 成本提示 | CPU 上涨而调用量持平 | 检查该 Worker 的部署记录和慢路径 | — |

证据门槛：

- 封锁、质询和限速建议至少需要一条中或高置信度的假设。
- 当 ≥ 70% 的增量是廉价的边缘流量时，不给出任何封锁类建议。
- 缓存和成本建议是结构性的，不受门槛限制。
- 敏感路径即 `path_rules` 和 `daily.paths` 中的全部模式。
- 网络类型先查内置的主要云 / 机房与宽带 / 骨干 ASN 表，再在套餐提供时根据 ASN 注册名称中的关键词判断；否则为「未知」。Cloudflare 自己的 ASN 和 `blocking.never_block_asns` 永远不会被建议。

路径模式按如下方式转换为表达式：`/x` → `http.request.uri.path eq "/x"`；`/x*` → `starts_with(http.request.uri.path, "/x")`；其他含 `*` 的模式 → `wildcard`。

## 日报 {#daily-report}

每天都发送（它是定时报告，不是告警）。第二行是「✅ 一切正常」或「⚠️ 需要关注：……」，之后每个问题一段（标题、数字、含义、建议），与小时告警相同。

- 过去 24 小时对比前一天：与小时级看守相同的各项指标（不经状态机）、缓存情况、回源最多的路径。
- 主要来源网络与主要访问者，新出现的标记为 `[new]`（中文报告为 `【新】`）；已验证的正规爬虫与冒充者。
- **例行检查：**
    - 按规则统计的防火墙事件（带规则名称），以及最常被拦截或质询的 IP——在没有该数据集的套餐上显示「不可用」，绝不显示 0；
    - FlareHound 的每个封锁项及其在窗口内的尝试量、开始时间和到期时间——等尝试停止了再解封，而不是看起来安静了就解封；
    - 窗口内新增的封锁及其封前/封后裁决；如果是在[模拟](simulator.md)之后确认的，附上预测净新增与规则实际拦截量；
    - **规则模拟器准不准**（近 30 天）：事先做过预测的封禁数、已核对数，以及实际相对预测（每小时）的通常偏差与最大偏差——「规则模拟器准不准（近 30 天）：4 次封禁事先预测过能多拦多少，已核对 3 次——实际与预测相比（每小时）：通常偏差 −11%，最大偏差 +85%（AS45102）」；
    - `daily.paths`：每条路径的回源量对比其 `max`（✓ / ⚠）；
    - `daily.artifacts`：已知的记账假象，与访客错误分开计数。
- 处置建议（不含限速建议：日报没有按 IP 的数据）。
- WAF 规则体检摘要：没问题时一行，只对需要关注的项给出细节。
- 仍未结束的小时级异常及其开始时间（放在问题段落之前）。
- **系统状态**（有变化时显示，每周提醒一次）：套餐不含 ASN、读不到防火墙事件、本地历史与 4 周平时水平的积累进度（附 `flarehound -backfill 28` 提示）、[计数口径](archive.md#calibration)、访问目的对照表版本。上次显示的内容记录在状态文件旁的 `*-status.json` 中。
- 数据缺口：任何失败的查询都会点名，而不是悄悄报成零（每次都说）。

按需运行：`flarehound -daily`（加 `-dry-run` 则打印而不发送）。
