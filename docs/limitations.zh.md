# 限制 {#limitations}

FlareHound 把自己的局限摆在前面说清楚，而不是让你自己去发现。

## 数据 {#data}

- **抽样的分析数据。** Cloudflare 的 adaptive GraphQL 分析数据是抽样后外推的。在小站点上，细粒度的拆解可能不稳定，低流量路径可能返回 0 行——零并不代表不存在。超大型站点会觉得归因太粗；FlareHound 面向的是中小型站点。
- **与面板口径不同。** adaptive 计数包含 Worker 子请求和缓存操作。在一个实际运行的 Free zone 上，FlareHound 测得的请求数约为面板的 1.29 倍，边缘 5xx 约为 1.84 倍（缓存操作造成的记账假象）。阈值以 FlareHound 的口径计；见 [口径校准](archive.md#calibration)。
- **写入延迟**（约 5–10 分钟）决定了检测的下限。这是一只看门狗，不是实时护盾——护盾仍然是边缘规则。
- **没有来源页面维度。** 最多只有 referer 的 host（付费套餐），流量无法按来源页面拆分，因此无法从分析数据中检测「伪造 referer 绕过」。
- **Worker CPU** 只提供分位数（FlareHound 使用 P50），没有总量；任何成本解读都只是估算。
- **保留期。** Cloudflare 保留约 31 天。`-backfill` 最多能找回最近 30 天；更早的数据无法重建。归档保存的是小时聚合，从不保存单个请求。
- **数据库文件会趋于平稳，旧文件永不缩小。** 被清理的行释放出的页会被新行复用。只有 v1.18 或更高版本创建的 `archive.db` / `console.db` 文件会在一次大规模清理后（例如调低 `archive.hourly_retention_days` 之后）把空间还给磁盘；早期版本创建的文件不会被重建，保持原有大小。见 [磁盘空间](archive.md#disk-space)。

## 套餐 {#plans}

分析数据开放哪些内容取决于套餐。FlareHound 会探测每个 zone，能力不足时降级而不是失败。在一个实际运行的 **Free** zone 上验证的结果：

| 能力 | Free | 缺失时的影响 |
|---|---|---|
| `clientAsn` | 不可用 | 没有 ASN Top 榜、没有新 ASN 检测、没有 ASN 建议；日报会说明这一点 |
| `clientASNDescription` | 不可用 | 网络类型只来自内置表 |
| 防火墙事件数据集 | 不可用 | 防火墙事件、封锁尝试量、体检命中统计和 `--observe` 显示「n/a」——绝不显示 0 |
| `verifiedBotCategory` | 可用 | 用于爬虫核验 |
| Host 与国家维度 | 可用 | — |

规则额度也因套餐而异（自定义规则 Free 5 / Pro 20 / Business 100 / Enterprise 1,000；限速规则 1 / 2 / 5 / 100），并且在 Free 上，限速周期和缓解超时都必须是 10 秒。

## 检测 {#detection}

- **硬阈值。** 缓慢增长（每天 +5%）和刻意压在线下的攻击都看不见；正当的流量激增（新品发布、内容爆火）在数字上与攻击看起来一模一样。
- **基线问题。** 如果昨天本身就不正常，对比就会失真。4 周中位数基线（归档样本足够后启用）能减轻这个问题，但持续时间很长的异常仍可能变成新常态。
- **不懂语义。** 规则无法知道一个新 ASN 是爬虫集群还是你自己新上的服务。请把已知来源登记在 `known_faces` 下。
- 封锁时不测量**按网段的占比**（分析数据无法按网段过滤）；FlareHound 会在封锁计划中说明这一点。国家封锁由确认页的[模拟](simulator.md)计量——只能说有多少流量，说不出其中多少是真人。
- **归属地是库的解读，不是事实。** 它是一个地址的注册/路由所在国家——住宅代理显示的是其出口，数据中心地址显示的是其数据中心——而且不同的库在边缘情况下会有分歧（DB-IP lite 把 Google 的 IPv6 解析器 `2001:4860:4860::8888` 放在 CA，GeoLite2 放在 US）。我们刻意没有基于它构建按国家的流量视图：从 Top IP 推断出的国家分布会是一个严重有偏的样本。
- 检测链路中没有 AI：发现是确定性的，用同样的数据可以复现。

## 规则模拟器 {#rule-simulator}

见 [规则模拟器](simulator.md)。先写清边界，再谈功能：

- **采样近似，不是回放。** 没有回放 API；表达式被翻译成采样聚合分析数据上的过滤条件。采样就是精度上限——背后没有 Logpush，也没有逐请求日志。
- **referer 只能到 host 级**（付费套餐）。对完整 referer 的比较（「恰好等于首页」）会被放宽到其 host：报告标为*上界*，并点名该子表达式。处于否定之下时不可评估。
- **Free 区**没有 ASN 维度，也没有防火墙事件：ASN 表达式在该区不可评估，净新增不可用。报告如实说明，不用其他口径凑数。
- **净新增是拼接估计。** 命中来自 HTTP 请求数据集，已处理与前置跳过来自防火墙事件——两套数据采样口径不同。规则位置需要读令牌有 Zone → WAF: Read；没有时按全规则集口径估计。前面某条 skip 规则不记日志又无法翻译时，净新增为上界。
- **挑战通过率是有偏样本。** 防火墙事件只含遇到过挑战的请求：区间只作参考，不作预测。
- **`$list`** 只展开读令牌读得到的 IP 与 ASN 列表（Account → Account Filter Lists: Read），最多 1,000 个单值；托管列表 `$cf.…`、含网段的列表与 hostname 列表不可评估。
- **不可评估、只能取界：** header、cookie、请求体、正则、通配、威胁与 bot 评分、速率、除 `starts_with` / `ends_with` 外的函数、无法展开的 `$list` 引用与网段。这类子项会被点名并取界（上界按命中、下界按不命中）；计数变为上界，命中另给下界。若没有可评估的部分来收窄表达式（上界就是整个 zone），则完全不给数。

## 范围 {#scope}

- 只支持 Cloudflare。源站内部（进程、数据库）不在范围内。
- 每个部署一个进程；运行在你自己的机器上。不提供 Cloudflare Workers 部署方式。
