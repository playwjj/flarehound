# Web 控制台 {#web-console}

控制台是与看守并列的第二个进程。它读取看守写入的归档（`data/archive.db`），并维护自己的账号数据库（`data/console.db`）。看守从不打开账号数据库。背景见 [Web 控制台改版说明](web-console-revision.md)。

没有写 Token 时控制台是只读的。把写 Token **只交给控制台进程**，管理员就能在控制台里封锁、解封和修改到期时间（[在控制台中封锁](#blocking-from-the-console)）；看守绝不能持有它，`flarehound doctor` 会同时检查这两点。

**语言。** 控制台支持英文和中文：页头（登录页也有）的 **EN / 中文** 按钮为当前浏览器切换语言，已登录账号的选择会在所有设备上保留。默认语言取 `report.language`。规则说明、审计修复建议和配方跟随查看者的语言；快照使用创建者的语言，密码重置邮件使用该账号的语言。通知不受影响。

## 开启 {#turn-it-on}

```json
"console": { "enabled": true }
```

先创建第一个管理员，然后启动：

```bash
flarehound -config config.json console init-admin --user you
flarehound -config config.json console
# flarehound … console listening on http://127.0.0.1:8640 (read-only)
# … or "(blocking enabled for admins)" when CF_WRITE_TOKEN is in its environment
```

如果还没有任何账号，控制台还会在日志里打印一个一次性设置链接（`/setup?token=…`），用它创建第一个管理员后即失效。

在 Docker 中，`docker-compose.yml` 里有一个可选的 `flarehound-console` 服务（profile `console`），使用同一个镜像和数据卷。它在容器内监听 `0.0.0.0:8640`（`console --listen`），只发布到宿主机的回环地址：

```bash
docker compose --profile console up -d
docker compose run --rm flarehound-console console init-admin --user you
```

要在控制台内封锁，设置 `CF_CONSOLE_WRITE_TOKEN`（以 `CF_WRITE_TOKEN` 的名字传给该服务）——永远不要把写 Token 交给 `flarehound` 看守服务。要使用 Google / GitHub 登录，设置 `GOOGLE_OAUTH_SECRET` / `GITHUB_OAUTH_SECRET`。

## 从手机访问 {#reaching-it-from-your-phone}

FlareHound 不做 TLS，也不对公网暴露——控制台默认监听 `127.0.0.1`。把它放在你已经信任的东西后面：

- **Tailscale**：`tailscale serve --bg 8640` 会给你一个 `https://<machine>.<tailnet>.ts.net`。
- **Cloudflare Tunnel**（可在前面再加 Cloudflare Access）。
- **TLS 反向代理**（Caddy、nginx）。

然后把 `console.base_url` 设为该地址，并在 `console.trusted_proxies` 中列出代理（代理与控制台在同一台机器上时例如 `"127.0.0.1"`）。只有这样，控制台才会信任 `X-Forwarded-For` / `X-Forwarded-Proto`、给会话 Cookie 加上 `Secure`，并在日志里记录真实的客户端 IP。来自其他机器的明文 HTTP 连接会在每个页面上显示警告，`flarehound doctor` 也会报告。

设置了 `base_url` 后，告警链接到涨降榜，恢复和日报链接到总览，规则集变更审计链接到 WAF 审计页。

## 页面 {#pages}

| 页面 | 回答什么问题 |
|---|---|
| **全部站点** | 有多个 zone 时，首页把它们按最需要关注的顺序列出：有未结束的告警事件、源站不可达、源站 5xx 超线、其他指标超线、24 小时内出现新面孔、最近有告警、数据过期。点击某个 zone 进入其总览。 |
| **总览** | **最近 60 分钟，实时**：用看守自己的查询向 Cloudflare 查询（每分钟最多一次），为避开入库延迟截止到几分钟前，并标为*未落定*，对照由其跨越的两个整点小时混合而成的 28 天基线。下面是归档中最新一个已落定的小时。每个指标显示其变化、告警线和状态（正常 / 留意 / 超线；522/524 记账底量和基线仍在积累中的新指标显示为中性状态）；48 小时图表附基线。实时查询失败时，显示已落定的小时并附说明。 |
| **涨 / 降榜** | 谁在涨，谁在降：User-Agent、ASN 和未缓存路径，按相对基线的绝对变化量排序。点击某一条目即可**下钻**：它的路径、状态码、缓存状态、另一个维度（某 User-Agent 的 ASN、某 ASN 的 User-Agent）以及它的客户端 IP，当前与昨天同一小时对照，每一部分都可以继续下钻。客户端 IP 带有 *封禁…* 链接，以及一行说明：是否由单个地址主导（≥ 30 %：封这个 IP），还是来源分散（没有一个达到 1 %：改为在 ASN 或路径层面处置）。 |
| **新面孔** | 最近 24 小时 / 7 天 / 30 天内首次出现的 User-Agent、ASN 和路径，以及它们当前的量。`known_faces` 中的条目会被标记。 |
| **IP 榜** | 哪些客户端地址在持续访问这个 zone。**最近 60 分钟**（实时，与总览相同）或 **24 小时**（由归档汇总，归档从 v1.14 起保存每小时前 50 个地址）：请求数、占 zone 的比例、[IP 归属地](configuration.md#geoip)（`(IN)`，悬停显示国家名称）、带 24 小时条带的*出现小时*（按持续性或请求数排序）、在边缘被拦下的比例、所属网络，以及每个地址的 *封禁…*（有生效中的 IP 封锁覆盖它时显示*已被 FlareHound 封禁*）。IPv6 按 /64 汇总；同一 /24 有两个或以上地址上榜时，IPv4 按 /24 汇总（其中最大的几个地址列在下方，每个都可下钻）。Cloudflare 核验为已知机器人的地址（真正的 Googlebot、Bingbot……）折叠在底部的*认证爬虫*（Verified bots）中——假冒的爬虫不会通过核验，仍留在榜上；你标为已知的网络中的地址也会折叠。其他爬虫所在网络只打标签，从不折叠（AS8075 既是 Bingbot 也是 Azure）。每个地址都可下钻到它的路径、状态码、缓存状态和 User-Agent。 |
| **历史** | 24 小时 / 7 天 / 30 天（或截至所选日期）：请求数与 `dynamic` 对照 28 天同时段 P25–P75 区间带，外加告警、恢复、封锁、解封、到期和规则变更的时间线。 |
| **WAF 审计** | 与 `flarehound audit` 相同的审计，缓存 30 分钟；可按需重新运行（每分钟最多一次）。 |
| **封禁** | 有写 Token 时：Cloudflare 中实际存在的封锁，与审计日志关联，显示每条封锁以来的尝试次数（Free 套餐为近似值）、实时查询的最近一小时（附最近一次被拦时间以及事件数据覆盖到多远）、到期时间、规则额度，以及到期的封锁是否正在被解除；可解封、改期、撤销、查看封前 / 封后。没有写 Token 时：显示审计日志中的视图。 |

除了实时小时和下钻之外，所有数字都来自归档中已落定的小时窗口——与告警使用的窗口、查询和基线完全相同。实时小时在滚动窗口上使用相同的查询；下钻实时查询 Cloudflare（它保留约 31 天），每个拆解结果缓存 10 分钟。

已有启用中的自定义规则作用于其上的 User-Agent 和 ASN 会被打上标签（「已被规则 #3 拦截」，或在规则还依赖路径时显示「规则 #N 视条件拦截」）：它们的量包含了被该规则拦下的请求。

### 读懂涨降榜 {#reading-the-movers}

归档为每个维度保存每小时的 Top N。某个条目在某小时低于榜单末位时，就没有那一小时的精确计数，于是控制台用该末位作为**上限**，并标记为 `<`：

- 基线为 `< 500`：该条目大部分时间不在榜上，它的常规量低于约 500。此时变化量按 500 计算——这是一个保守的数字，标记为 `≈`。
- 已经掉出当前榜单的条目不会显示为“降到零”的下降者；基线只是上限的条目根本不会显示为下降者。

路径涨降榜和路径新面孔统计的是未缓存请求——也就是昂贵的那部分。路径历史从 v1.3 开始。

## 在控制台中封锁 {#blocking-from-the-console}

持有写 Token 的控制台中，管理员在涨降榜和新面孔页面的 User-Agent 与 ASN 旁会看到 **封禁…** 链接（预填表单），在封禁页上会看到 **新建封禁**。每次变更都经过相同的步骤：

1. **表单**——目标、动作（默认：IP / UA 为封锁，ASN / 国家为质询）、时长、原因。
2. **审阅**——对于 IP，显示它的 [IP 归属地](configuration.md#geoip)、网络（ASN 及类型）和最近 24 小时的请求数，并附说明归属地能说明什么、不能说明什么；确切的变更（机制、规则改后的样子、规则额度）、实测占最近一小时超额流量的比例，以及每一条护栏警告，与 CLI 显示的完全一致。受保护的目标（你的源站、Cloudflare、`never_block`、保留地址段）在这里就会被拒绝。此时还没有任何改动。
3. **执行**——需要经过审阅（一个令牌，绑定到所审阅的确切内容和审阅人，15 分钟内有效）；在封锁可能误伤真实用户的情况下（eyeball / 未知 ASN、国家），需要手动输入目标；启用 TOTP 的账号还需要一个新的二次验证码。服务器端会再次运行护栏：页面本身永远不被信任。
4. **记录、变更、验证**——控制台审计日志在触碰 Cloudflare *之前*以你的账号记下请求，之后再记下结果；归档的封锁日志把操作者记为 `console:<account>`。变更完成后从 Cloudflare 读回核对。

**解封**和**改期**（+24 小时、+7 天、+30 天或永久）也走同样的步骤。

**撤销**出现在封锁日志的每一条记录上：它会打开反向变更的审阅页——封锁→解封、解封→重新封锁（预填表单）、改期→恢复原到期时间——并经过同样的确认流程。只能撤销某个目标最新的一条记录。

**封前 / 封后**：每次对比都以一句话结论收尾（「请求 45,000 → 900（−98%），已基本归零」「请求仍在继续，但 95% 被拦下（403）」「效果不明显，请检查规则是否命中」）；日报会列出当天新增的封锁及其结论。对每条封锁，控制台比较其生效前一小时与生效后一小时——目标的请求数及占 zone 的比例、它的状态码（被拦的请求仍会计入，记为 403）、zone 总量，以及规则的尝试次数。在那一小时落定后自动计算（之前显示部分对比），并在历史时间线上标出该封锁。

**到期**：持有写 Token 的控制台会自行解除到期的封锁，每 5 分钟一次，在两份审计日志中都记为 `system:expiry`（v1.16）。封禁页显示到期解除最近一次运行的时间；当有封锁设置了到期时间却没有任何进程在解除它们时（既没有持有写 Token 的控制台，也没有 `flarehound enforce`），会发出警告。

**位置与绕过**：审阅页会显示承载该目标的规则所在位置（"inserted at #4, after … and before …"，即插在第 4 位、某规则之后、某规则之前）——在 zone 的放行（skip）规则之后、质询和封锁规则之前——若前面有某条放行规则会让该目标通过，则显示红色警告（见[封锁](blocking.md)）。

**二次验证提示**：当控制台持有写 Token 而 `console.require_totp` 关闭时，管理员会一直看到一条横幅，直到该选项被打开，或有管理员明确选择保持关闭（记入审计日志）。

CLI（`flarehound block / unblock / blocks / enforce`）保持不变，在控制台不可用时仍是后备手段。

## WAF 规则 {#waf-rules}

**WAF 规则**按执行顺序列出 zone 的自定义规则和限速规则，每条附一段大白话解释（「如果路径以 /login 开头，且不是 Cloudflare 已核验的爬虫 → 托管质询」）、它的动作和状态。它用只读 Token 读取规则（Zone → WAF: Read；额度需要 Zone: Read）。

有写 Token 时，管理员还可以：

- **用配方添加规则**——配方目录逐个解释每个配方；表单只询问它需要的内容（路径、IP、一个秘密请求头……）；
- **启用 / 停用**、**上移 / 移到顶部**、**删除**规则；
- **恢复**备份（每次变更前都会备份一次）。

每次变更都经过一个审阅页——大白话描述的规则、确切的变更、变更后的额度、警告——并以与封锁相同的保护措施执行：审阅令牌绑定到所审阅的内容*以及制定方案时所依据的规则集版本*（如果期间有其他人改了规则，会要求你重新审阅）、启用 TOTP 的账号需要新的二次验证码、在触碰 Cloudflare 之前写入账号审计日志、阶段（phase）备份、读回验证，以及执行日志。FlareHound 自己的封锁规则会显示在这里，但在封禁页上管理。

规则和审计在后台保持预热（规则每 10 分钟重读一次，审计在超过 30 分钟时重新运行），所以两个页面都能立即打开；在控制台中做出的变更会刷新它们，规则页上也有刷新链接。配方会感知套餐：某个配方的规则类型已达套餐额度时，它会直接说明，而不是提供表单；Free 套餐的 zone 不会被提供它们没有的放行范围，其限速时间窗固定为 10 秒。

**WAF 审计**页把**怎么修**放在最前面——每项发现附上该怎么做，以及一个**用配方修复**链接（或 CLI 命令）——完整报告保留在下方。刚接触这些？看 [WAF 基础](waf-guide.md)。

## 只读快照 {#read-only-snapshots}

总览、涨降榜、历史、**WAF 审计**和 **WAF 规则**都有一个**生成快照**按钮（谁可以使用：`console.snapshots`——默认仅管理员，也可设为所有人或无人）。它把当前视图冻结成一个自包含的 HTML 页面——样式表内联、没有脚本、没有外部资源、不含账号数据或令牌——并给你一个**无需登录**即可打开的分享链接，有效期 24 小时、7 天或 30 天。可用于事件复盘，或在不给对方开账号的情况下，向站点团队或合作方展示现状。

**快照**页列出所有快照（管理员看到全部，其他人只看到自己的）：可以下载 HTML 文件，或随时吊销链接。创建和吊销都会记入账号审计日志。分享页面带 `noindex` 和严格的 Content-Security-Policy。

## 设置 {#settings}

管理员在页头可以找到**设置**：通知、告警线、已知面孔、网络命名，以及变更历史。它们保存在状态文件旁边的 `settings.json` 中，叠加在 `config.json` 之上，而 `config.json` 从不被修改（可以保持只读挂载）。不保存任何密钥——各渠道的密钥保存在环境变量里，控制台只设置这些变量的*名字*以及非机密参数（chat id、SMTP 主机、收件人……）。

每次变更都会显示确切的差异；对于告警线，还会用新的告警线**回放最近 7 天**（超线的小时数和事件数，现在 vs 修改后，以及哪些小时发生变化），然后需要一个新的二次验证码，并以你的账号记录下来。每个保存过的版本都会保留；**历史**可以恢复其中任意一个，包括“仅 config.json”。

**看守在下一轮开始前就会采用变更——无需重启——并在每个设置页上回报**：它正在运行的版本、已接受的更新版本，或某个**被拒绝的版本及原因**（例如某个环境变量在看守进程中为空）。被拒绝的变更永远不会让告警中断：之前的设置继续生效。对每个渠道，页面会显示它引用的哪些变量已在看守进程中设置。

**发送测试通知**会请看守用它自己的环境去发送——与告警走同一条路径——并在几秒内按渠道显示“已送达”或确切的错误。

**已知面孔**可以一键添加：在新面孔、涨降榜和下钻页面的 User-Agent 或 ASN 旁点 *标为已知*。**网络命名**：每个 ASN 都显示其注册名称和网络类型（由看守每小时记录，前提是套餐的分析数据包含 ASN 名称）；*命名* 可以给它起一个你自己的简短名称，在控制台和通知中使用。

## 账号 {#accounts}

- **角色**：`admin`（管理账号；在控制台持有写 Token 时可以封锁）和 `viewer`（查看、创建快照）。
- **不支持自助注册**。管理员在用户页创建账号（临时密码只显示一次；用户必须在首次登录时修改），或发出一个一次性邀请链接（72 小时）。
- **密码**：至少 10 个字符，以 argon2id 哈希存储。修改密码会让其他所有会话退出登录。
- **二次验证登录（TOTP）**：每个用户都可以在账号页中开启——用任意身份验证器 App 扫描二维码（或手动输入旁边显示的密钥）。`console.require_totp` 使其成为强制要求。启用 TOTP 的账号在进行账号管理之前需要确认一个新的验证码（step-up）。
- **限流**：每个 IP 每分钟 10 次登录尝试；连续失败 5 次会锁定账号 15 分钟（管理员可以解锁）。
- **会话**保存在服务器端，可以吊销：用户可以查看并结束自己的会话；管理员可以让任何人退出登录，或停用某个账号（同时结束其所有会话）。
- **审计日志**：登录、登录失败、密码和二次验证变更、账号管理以及审计重跑，附账号和 IP——在用户页上查看。

**忘记密码？** 配置了 `notify.email`（通知所用的邮件设置，SMTP 或 Resend）和 `console.base_url` 后，登录页会提供邮件重置：一个 30 分钟内有效的一次性链接会发送到账号登记的邮箱。无论账号是否存在，页面的回答都相同；每个账号每 10 分钟最多发一封邮件。重置会结束该账号的所有会话，且不会绕过二次验证登录。没有邮件时，由管理员重置密码（用户页），或使用下面的本地命令。

本地恢复（在机器上执行，无需 Web 登录）：

```bash
flarehound console users
flarehound console reset-password --user NAME
flarehound console reset-totp --user NAME
```

### 使用 Google 或 GitHub 登录 {#sign-in-with-google-or-github}

第三方登录是进入已有账号的**额外**方式——永远不是获得账号的途径：

- 每个人先用密码登录，然后在**账号**页中绑定 Google 和/或 GitHub（需要重新输入密码）。此后登录页上的 *使用 Google / GitHub 登录* 就对他们可用。
- 未绑定的身份登录不了任何账号。不会创建账号，也不会按邮箱地址进行匹配。
- 通过提供方登录之后，二次验证登录仍然适用，停用账号、强制修改密码和 `require_totp` 同样适用。密码照常可用。
- 用户在自己的账号页解除绑定；管理员在用户页上能看到每个账号绑定的身份，并可以移除。绑定、解绑以及每次登录都记入账号审计日志。

配置步骤：

1. 把 `console.base_url` 设为大家使用的 HTTPS 地址（提供方会重定向到这里）。
2. 创建一个 OAuth 应用，并注册重定向 URI `<base_url>/oauth/<provider>/callback`：
    - **Google**：Google Cloud console → APIs & Services → Credentials → *OAuth client ID*（Web application）。重定向 URI `https://…/oauth/google/callback`。
    - **GitHub**：Settings → Developer settings → *OAuth Apps* → New。Callback URL `https://…/oauth/github/callback`。
3. 配置 client ID，并把 secret 放进**控制台**进程的环境变量中：

```json
"console": {
  "enabled": true,
  "base_url": "https://hound.example.ts.net",
  "oauth": {
    "google": { "client_id": "1234-abc.apps.googleusercontent.com", "client_secret_env": "GOOGLE_OAUTH_SECRET" },
    "github": { "client_id": "Iv1.0123456789abcdef", "client_secret_env": "GITHUB_OAUTH_SECRET" }
  }
}
```

`flarehound doctor` 会打印需要注册的确切重定向 URI。配置了提供方后，控制台还会向该提供方发起出站连接（Google：`accounts.google.com`、`oauth2.googleapis.com`；GitHub：`github.com`、`api.github.com`）。

保护方式：带 PKCE 的授权码流程；`state` 值只能使用一次，10 分钟后过期，并且必须回到同一个浏览器（Cookie）；Google 的 ID token 会校验 issuer、audience、过期时间和 nonce；GitHub 账号按其数字 ID 识别（登录名可以改）。

### 位于认证代理之后 {#behind-an-authenticating-proxy}

当 Cloudflare Access、oauth2-proxy 或类似工具已经完成了身份认证时，控制台可以从它注入的请求头中获取身份：

```json
"console": {
  "enabled": true,
  "trusted_proxies": ["127.0.0.1"],
  "proxy_auth": { "header": "Cf-Access-Authenticated-User-Email", "default_role": "viewer" }
}
```

该请求头只在来自 `trusted_proxies` 时才会被读取（没有配置它们时，配置会拒绝 `proxy_auth.header`）。与本地账号的用户名或邮箱匹配的身份，以该账号的身份操作；其他身份获得 `default_role`（`viewer`，或 `none` 表示拒绝）。`disable_login: true` 会关闭密码登录表单。

## 安全说明 {#security-notes}

- 没有 JavaScript；严格的 Content-Security-Policy（`default-src 'none'`）；没有外部资源。
- 每个表单都带 CSRF 令牌；跨站 POST 会被拒绝。
- 保留期：过期的会话和登录状态每小时清理一次；快照的页面在其链接过期或被吊销 30 天后删除（记录保留）；账号审计条目保留一年，缓存的封前 / 封后对比保留 90 天。
- `console.db` 以 0600 权限创建，存有密码哈希和 TOTP 密钥——要像备份凭据库那样备份它。
- `flarehound doctor` 检查：控制台是否开启、是否只监听回环地址、代理设置、账号与管理员，以及写 Token 在哪里：如果**看守**持有它则报错；对于控制台，检查是否启用了封锁——启用了且 `console.require_totp` 关闭时给出警告。
- 控制台持有写 Token 时，请开启 `console.require_totp`：这样每个能修改 Cloudflare 的账号都要用二次验证登录，并且每次变更都要用新的验证码确认。
